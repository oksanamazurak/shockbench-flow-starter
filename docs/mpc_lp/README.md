## Ключові факти

- **Куди йдуть гроші на small:** відключення електрики (shed) — 60%, нестача чипів — 39%, усе
  інше (freight, tariff, holding, disposal, черги, war-risk) — < 1%. Нестача чипів теж здебільшого
  наслідок нестачі електрики на fab. Тюнінг "дрібних" компонентів вартості не має сенсу.
- **98% shed — тижні нестачі конкретного палива в grid.** Паливо не взаємозамінне: кожне дає не
  більше `share_k · G_bar`.
- **Паливом краще керує просте правило** ("просити номінал або більше — середовище обріже"), ніж
  LP: модель grid у LP і перенаправлення черг на протоках обидва програли (див. `experiments.md`).
- **Оптимум деяких параметрів залежить від мережі** (`upstream_floor`, `fuel_mult`), тому вони —
  словники за `static["instance"]["kind"]`.
- **Числовий тюнінг вичерпано** на поточній структурі: пошуки дають плато. Покращення можливі лише
  через зміну структури.

## Правила для ШІ-агента, що продовжує роботу

1. Імпортувати в `agent.py` можна лише stdlib, numpy, scipy, torch (CPU) — сервер іншого не має.
   `sbf check` це перевіряє.
2. Оцінювати лише через `uv run sbf compare NEW OLD --task=small`. Зміна — виграш, тільки якщо 90%
   парний інтервал не містить 0. Підбирати параметри — на своєму root (`entropy=20261004`), dev
   (root 0) — лише для фінальної перевірки.
3. Перевіряти **кожну** мережу окремо: те, що допомагає на tiny, на small може обвалити оцінку.
4. Після зміни, яка має бути "лише рефакторингом", звіряти оцінку до і після на тих самих episodes.
5. Не змінювати файл, який читає фоновий пошук (`07_mpc_policy_search.py` і OpenEvolve копіюють
   `agents/mpc_lp/agent.py` для кожного кандидата).
6. Якщо пошук дає пласку оцінку на всіх кандидатах — спершу перевірити, чи LP розв'язується
   (`linprog(...).success`), а вже потім вважати це плато.
7. Не заливати на Codabench без прямого прохання користувача (5 спроб на день); не комітити без
   прохання; ніколи не показувати й не комітити `.env`.
8. Нові параметри додавати в `PARAMS` з коментарем: що це, значення, чим обґрунтоване. Вимкнені
   експерименти лишати під параметром із вердиктом у коментарі.
