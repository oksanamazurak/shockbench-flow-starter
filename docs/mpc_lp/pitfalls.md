# Пастки

Кожна з них уже коштувала час. Формат: симптом → причина → як уникнути.

## Оцінка й пошук

1. **Пошук дає ту саму оцінку на всіх кандидатах** (240 разів поспіль).
   → LP нерозв'язний щотижня, і агент тихо грає просте правило, яке від параметрів не залежить.
   → Перевіряти `linprog(...).success` по тижнях; сума `fallback_weeks` цього не покаже, бо внутрішній
   fallback агента — не fallback сервера.

2. **Виграш на train, нуль на dev.**
   → 4–8 тренувальних episodes дають великий шум (стандартна похибка оцінки на 20 episodes — 0.17–0.20).
   → Рішення приймати лише за `sbf compare` на dev (парний інтервал), а не за train-оцінкою.

3. **Зміна, що допомагає на tiny, обвалює small** (0.247).
   → Інша структура мережі (`terminal`-вузли, кілька OSAT packages, 7 проток).
   → Порівнювати на кожній мережі; параметри з різним оптимумом робити словником за `kind`.

4. **Фоновий пошук дає зіпсований результат.**
   → Під час пошуку змінили `agents/mpc_lp/agent.py`, а пошук копіює його для кожного кандидата.
   → Не редагувати агента під час пошуку; або шукати на копії.

5. **Середнє ховає катастрофи.** Варіант дешевший у 4 з 6 episodes, але в двох нестача коштує
   +339 / +168 млн $.
   → Дивитися розклад вартості по episodes, а не лише середню оцінку.

## Модель LP

6. **Жорсткий storage-ліміт робить LP нерозв'язним.**
   → У симуляторі надлишок на джерелах обрізається безкоштовно, а на інших вузлах утилізується за
   `disposal_cost`. Це вартість, а не стіна.
   → Модель: змінна `spill` (на джерелах безкоштовна, деінде `disposal_cost`); на протоках і grid
   ліміту нема.

7. **LP ставить 0 на upstream-слоти.**
   → LP цінує лише те, що можна простежити до вартості. Без моделі виробництва wafer нічого не
   вартий; без terminal value чип, що з'явиться після горизонту, теж.
   → Модель виробництва + terminal value + `upstream_floor`.

8. **LP вимикає електростанції** (+150 млрд $ shed на small).
   → Паливо, яке LP не вміє оцінити, потрапило під керування LP: на small лейни палива
   закінчуються в `terminal`, а не в grid.
   → Слоти палива визначати за товаром (`grid_fuels`), а не за кінцем лейна.

9. **Обмеження вивозу поточним запасом блокує ланцюг назавжди** (`cumulative_cap`, −1.94).
   → Буфер виробництва поповнюється щотижня, а запас на старті може бути 0.

10. **`bounds` зібрані до блоку, що задає `ub`.**
    → Нові верхні межі мовчки не діють.
    → `bounds = list(zip(lb, ub))` — останнім, перед поверненням.

11. **Прогноз з `warn_b = −5` вважає майже всі протоки закритими на h ≥ 1.**
    → Для лейнів LP це працює як обережність, але будь-яке правило "якщо попереду закрито — роби X"
    за цим прогнозом спрацьовує завжди (`reroute_forecast`: 0.117).

## Середовище

12. **Параметри, прив'язані до кількості слотів, ламають інші мережі.**
    → `fraction` на 20 чисел (tiny) на small: `ValueError: shapes (108,) (20,)`, усі тижні — naive.

13. **Позиція протоки в `warning.score` — не фіксована.** `layout["warning_units"]` складається з
    пар `[kind, index]`; шукати, а не писати `15 + c`.

14. **`override` / `release_mode` — лише для танкерних товарів** (lng, crude), не для чипів.

15. **Просте правило шле статичний `u0`, а не живий `graph_now.u`.** Це навмисно: середовище
    обрізає. Тести, що вимагають `flows ≤ graph_now.u`, хибні для слотів простого правила.

## OpenEvolve і Claude CLI

16. **"No valid diffs" на кожній iteration (opus, бюджет $0.5).**
    → CLI повертає текст `Error: Exceeded USD budget` замість відповіді.
    → sonnet і бюджет ≥ $1; перевіряти ручним викликом `claude -p` з тим самим промптом.

17. **"Generated code exceeds maximum length".** → `max_code_length` у config (агент ~41 KB).

18. **"Argument list too long".** → Промпт іде одним аргументом CLI, а Linux обмежує його 128 KB.
    Що більше програм в архіві, то частіше. Зменшити `num_top_programs` / `num_diverse_programs`
    або сам файл.

19. **Кандидат не бачить `params.json`.** → OpenEvolve пише кандидатів через `NamedTemporaryFile` у
    `/tmp`; оцінювач копіює `params.json` поруч (завжди перезаписує, щоб не взяти застарілий).

20. **Серії швидких "No valid diffs" / порожніх відповідей.** → Нестабільність CLI при частих
    викликах; ручний повтор того самого промпту зазвичай працює. Перезапуск прогону допомагав.

21. **LLM мутує не те.** На широкій задачі (три блоки) LLM майже весь час крутив формулу прогнозу,
    а блок палива змінював лише косметично. Давати один вузький блок із конкретною метою.

## Інструменти

22. **`pkill -f <шаблон>` убиває власну команду**, якщо шаблон є в її ж рядку. → Зупиняти фонові
    задачі через task id.

23. **`sbf token` через `!` у Claude Code падає з `EOFError`** (нема stdin). → Звичайний термінал.

24. **Подвійне фонове виконання** (`&` всередині фонової команди) — процес не відстежується.
