# Зміни в `agents/mpc2/agent.py`

Усі зміни — в `agent.py` (параметри в `DEFAULTS`, увімкнення по борду в `TINY_OVERRIDES`, `SMALL_OVERRIDES`,
`FULL_OVERRIDES`, вибір за `T` з `config`). Вкладений пакет `sbfv/` не змінювався: де треба змінити його
поведінку, це зроблено обгортками в `agent.py`.

Позначення: `small-val`, `full-val` — набори `benchmarks/suites.yaml` (`sbf bench`, економія відносно naive);
dev — 20 епізодів `sbf compare` (RSS). Інтервали — парні 90 %.

## Full

### `bf_passes 0` (FULL_OVERRIDES)
Повторні розв'язки base-first на full займали медіану 2.3 с, до 12 с; ≈12 % тижнів ішли naive.
Без них: full dev 0.407 → 0.449.

### `long_fuel_days 90` (FULL_OVERRIDES)
Ядерне паливо мережі `grid_us` має запас на рік (364 дні) і доставку 8 тижнів. Вікно бачить великий запас і не
дозамовляє; на 104 тижнях запас закінчується ≈64-го тижня, мережа скидає до кінця (157 тис. одиниць за епізод
проти 17 тис. у naive). Слоти палива з покриттям ≥ 90 днів тепер відправляють не менше, ніж naive
(`self.policy._fallback`). Full dev 0.449 → **0.672** (+0.22, [+0.161, +0.279]). На small вимкнено
(−0.0013 на `small-val`: річного запасу вистачає).

### `fuel_mult 10` (FULL_OVERRIDES)
Множник замовлень палива для мереж (важіль із `agents/mpc_lp`). `full-val` +0.0051 [+0.0010, +0.0089];
на small без ефекту.

## Обидва борди

### `terminal_scale 1.0` — ціна запасу на кінці вікна
Вікно оцінює запас на останньому тижні лише за ціною залишку, тож паливо й сировина поза вікном «нічого не
варті». `scripts/terminal_values.py` розв'язує ясновидну задачу на окремих епізодах (small: корінь 9301,
60 епізодів; full: 9401, 48 епізодів) і бере маргінали рядків балансу запасів ("balance", t, slot): скільки
заощадила б одиниця запасу в тиждень t. Середнє по епізодах — `agents/mpc2/terminal_<task>.npz`, масив
`value (T+1, slots)`. `_terminal()` ставить на змінні запасу останнього тижня вікна ціну
`-terminal_scale * value[end, slot]` (не нижче за наявну). Якщо вікно сягає кінця епізоду — нічого не міняє.

| Перевірка | Результат |
| --- | --- |
| `small-val` | 0.25: +0.0038, 0.5: +0.0042, **1.0: +0.0043 [+0.0032, +0.0055]** |
| small dev | 0.7887 → 0.8021 (+0.0134 [+0.0034, +0.0249]) |
| `full-val` | +0.0094 [+0.0076, +0.0113]; без `long_fuel_days` +0.0085 |
| full, цінність з 48 епізодів замість 16 | +0.0010 [+0.0000, +0.0021] |
| `terminal_scale` 1.5 / 2.0 на full | −0.0008 / −0.0006, не відрізнити |

Для tiny файлу немає — там нічого не змінюється.

## Small: робочі тижні фабрик

Правило base_first: у тиждень, коли мережа скидає базове навантаження, її фабрики не отримують енергії.
Лінійна задача цього не бачить і планує фабрики в такі тижні. Точний (MIP) розв'язок показав, що оптимум
скидає стільки ж, але зосереджує скидання в менше тижнів, а решту тижнів фабрики працюють; частка робочих
тижнів сильно різна між мережами (6–100 %).

### `bf_adapt 0.6` (SMALL_OVERRIDES), `_cycle()`
Для мережі, яка за планом скидає частку s навантаження, частка «робочих» тижнів `0.6 · (1 − s)`, рівномірно.
У робочих тижнях скидання оцінюється ціною `_base_first_price` (V / min e_f), у решті енергія фабрик = 0.
Один додатковий розв'язок. `small-val` +0.0038; small dev 0.7776 → 0.7887; борд 0.7456 → 0.7694.
Варіанти: 0.5 +0.0034, 0.8 −0.0043, 1.0 −0.0162; фіксований цикл `bf_cycle` 2/3 — +0.002 (незначимо), 4 — гірше.

### `bf_search [0, 0.15, 0.3, 0.5, 0.75, 1]`, `bf_search_roundrobin`, `bf_search_cpu 0.6`
Для мережі, що скидає, перебираються ці частки; лишається та, з якою витрати вікна (цільова функція LP) менші.
Щотижня — одна мережа по черзі (рівномірне навантаження), після тижня довшого за 0.6 с перебір пропускається.

| Варіант | Результат |
| --- | --- |
| 3 частки, усі мережі щотижня | `small-val` +0.0052; small dev 0.8021 → 0.8245; борд 0.7909, але 113 тижнів naive |
| 3 частки раз на 4 тижні + запобіжник | ≈ той самий результат, naive 39 → 16 тижнів (12 процесів) |
| **6 часток, одна мережа на тиждень + запобіжник** | +0.0035 [+0.0018, +0.0055] до попереднього; small dev **0.8316** |
| 11 часток по одній мережі | −0.0048 (і −0.0038 навіть без проблем з часом) |
| 6 часток для всіх мереж щотижня | −0.0050 |
| 5 часток для всіх мереж щотижня (до запобіжника) | −0.0022, 159 тижнів naive |

На full усі варіанти не вміщаються в бюджет або гірші: див. [research.md](research.md#full-робочі-тижні-фабрик).

### `bf_sim_select` (вимкнено)
Вибір частки за витратами плану у вкладеному симуляторі (`_sim_score`: потоки й пропуски черг за кожен тиждень
вікна, запас на кінці за ціною запасу) замість цільової функції LP. `small-val` (16 процесів): 6 часток −0.0043,
11 часток −0.0072. Лишено вимкненим як інструмент.

### `bf_cycle` (вимкнено)
Фіксований цикл робочих тижнів (кожен P-й). Замінено на `bf_adapt`.
